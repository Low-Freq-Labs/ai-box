# Prerequisite assessment stop guard

Sonny's direction relayed by Rick 2026-10-09 22:15 CDT authorizes this infrastructure implementation. It supplements the agent contract, not task acceptance or destructive authority.

`project-assess PROJECT --template` reads the complete project under its existing lock and emits all task IDs/revisions plus ready/blocked disposition placeholders. The agent traces prerequisites, performs independently available work, then fills summary, dispositions, and hashed evidence. `--submit /absolute/file.json` validates and atomically records the caller's assessment; `--check` revalidates it. Receipts expire after 30 minutes. Every task revision in the project (including completed source dependencies) contributes to the fingerprint. Exact referenced file hashes are checked again at use. Root-owned shared program, caller-owned mode0700 receipt directory, mode0600 receipt; no secrets are stored in receipts, only supplied reasons/references/hashes.

A disposition can group task IDs sharing one concrete prerequisite. Each requires kind, reason, next_step, owner, and evidence paths present in the top-level evidence mapping. Allowed kinds: unavailable_access, operator_decision, external_condition, owned_elsewhere, outside_role. Missing code/contracts/tests/reviews is not a kind. Ready work accepts only outside_role or a verified active other-owner prerequisite; otherwise claim and resolve or truthfully block first. Owned_elsewhere verifies active_task_id and owner against this project's actual current active queue. Cross-project handoffs can be pinned as evidence but are not accepted as machine-verified owned_elsewhere; record the role boundary explicitly and keep semantic review honest. A handoff alone is not proof the recipient is underway.

`project-assign inactive` requires a current assessment under the same exclusive project lock as directory removal, even for an already-inactive call. Active task abandonment remains refused. No task state is changed by assessment. Existing task-done remains a factual completion operation: completing a task is not the same as permission to stop working.

A managed Codex Stop command hook checks projects on which the caller is currently assigned. Missing/stale assessments or owned active work cause one corrective continuation prompt directing the agent back to prerequisite selection. A repeated stop (`stop_hook_active=true`) surfaces unresolved-gate status without another continuation. This is deliberate bounded friction, not an absolute prohibition on ending turns. The hook does not monitor unassigned projects, infer semantic completion from assistant text, inspect transcripts, send communications, or poll. Once an assignment was legitimately removed, later unrelated project changes do not automatically reactivate that agent.

Explicit assessed exceptions: operator_pause, operator_cancel, infrastructure_failure, budget_exhausted. They require reason and pinned evidence; they do not change active task state. The guard checks presence/freshness, not whether natural language proves operator authority. Native Interrupt and runtime resource limits remain outside Stop interception. Hook launch/config errors and repeated continuation can leave a turn ended without acceptance: always report this limit, never claim enforcement against hostile agents, manual filesystem edits, disabled/replaced clients, or process death. Existing FREQ_BOARD_TESTING overrides remain fixture controls, not a security boundary.

No new daemon, timer, messenger, auto assignment, automatic completion, or operator spam. System hooks are loaded by supported local Codex configurations; cloud orchestration may not execute local hooks. Existing sessions must be verified/reloaded by their owner if they do not pick up managed config. This deployment will not restart agent sessions. Supporting primary documentation: https://learn.chatgpt.com/docs/hooks (Stop, Interrupt, managed hooks; fetched 2026-10-10). Installed codex-cli0.160.0 reports hooks stable/enabled; runtime fixture probe records the actual behavior separately.

Example empty project assessment: generate template, retain schema/project/agent/revision, set summary to the actual checks and outcome; dispositions=[] and evidence={} are valid only with no ready/blocked work and no owned active work. For external evidence, add absolute-path:SHA256 pairs to evidence and reference those paths from each disposition. Do not set hashes to placeholders. Do not automatically fill decisions from the board's existing blocked labels.

Outside-role is not a blanket dismissal of frontend/backend dependencies: name the concrete next owner and handoff, then check independent work. Receipt storage is /home/freq-agents/session-data/<agent>/stop-assessments/ (caller-owned 0700); the initial /var/lib receipt location was rejected by the live session write boundary and superseded. Do not bypass a denied write. Shared tool setup must preserve these three commands, freq_stop_gate.py, the managed Stop configuration, and per-agent assessment directories; a future setup-board reinstall must include this release overlay. The maintained setup-board source includes this overlay; older setup copies need it before reinstall.

## Pause diagnostics and explicit refresh

`project-assess PROJECT --status` emits bounded read-only diagnostics after full board/evidence validation. Assessment expiry and persistent operator-pause proof/ownership are separate fields. Exit zero means the diagnostic ran, not that its reported states are all valid. `--check` retains strict assessment semantics. A valid pause does not accept unfinished tasks or authorize resumption.

Plain assessment submission reports an existing pause as unchanged. `--submit FILE --refresh-pause` explicitly replaces copied proof for an existing caller-owned pause, under the exclusive project lock, with current immutable evidence and no new owned task IDs. It cannot recreate a pause cleared by an explicit active assignment. Current rolling session-state paths are rejected when creating/refreshing pause proof; existing markers are still checked under their prior evidence contract. The assessment and pause files are individually durable, not a crash-atomic pair; a partial-write error reports this and requires status inspection before recovery.

`project-list --diagnostic` can show unaffected inventory when pause proof is invalid. Its invalid-proof rows are labelled and the command remains nonzero; the default discovery still fails closed. Structural board errors are not suppressed.

Managed Stop configuration and hook execution policy are unchanged by this repair. Owners can use `agent-skills check|sync --runtime codex` (or claude) to check/refresh their published managed instructions, with private backups; no peer-home access or agent restart is required. Maintained setup includes the helper and skill. Hook settings are not refreshed by this skill-copy command.
